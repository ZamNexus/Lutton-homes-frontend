# Luton Homes: website (frontend)

Static website for Luton Homes: five short-stay homes near Luton Airport (EasyStay, Luton Lodge, EasyStay Studio, The Garden Studio, The Garden Nest), 34 Beaconsfield, Luton LU2 0RW. Plain HTML, CSS and JavaScript generated by one Node script. No framework and no dependencies.

**Status: Phase 1, design approval.** Live preview: https://lutton-homes.vercel.app/ (client's favourite: `/d/client-original/`). Prices, beds, amenities, fees and rules are sample values until the owners confirm them. Every page is `noindex`. The API is in the separate repository `Lutton-homes-backend`.

## Commands

```
node build.mjs          # writes dist/ (9 designs, 209 pages)
node tests/check.mjs    # links, alt text, size budgets, no dashes in assets
python3 -m http.server 8099 --directory dist
```

## Layout

| Path | What |
|---|---|
| `build.mjs` | The build: templates in `src/` plus `data/homes.json` become pages under `dist/d/<design>/` |
| `src/pages`, `src/partials` | Shared page templates (`{{key}}`, `{{{raw}}}`, `{{> partial}}`) |
| `src/designs/<id>/` | Per-design overrides: `pages/`, `partials/`, `design.css`, `design.js` |
| `src/*.js`, `src/*.css` | Browser scripts and shared styles (cal, ui, book, review, admin, admin-report) |
| `data/homes.json` | The five properties (sample values) |
| `public/` | Fonts, photos, favicon and the Requirements checklist page |
| `tests/check.mjs` | The site checks |
| `vercel.json` | Vercel settings and security headers (CSP, frame, HSTS) |

## Connecting the API

Without an API address the site is a preview: the calendar shows sample availability, booking and review pages send nothing, and the owner sign-in is a preview gate. Build with the API address to switch it on:

```
API_URL=https://your-api.example.com node build.mjs
```

With the API on, `/admin/login/` also offers Continue with Google and an emailed code (shown only for the methods the API reports on `GET /api/auth/methods`), and `/account/` lets a guest sign in the same way and see their own bookings. The session token returns in the address fragment after Google, is kept in `sessionStorage` for the tab, and is never put in a query string. Code: `src/signin.js`. No Google script or image is loaded on the site; the button is a plain link to the API.

Then properties come from `GET /api/homes` (falling back to `data/homes.json` if unreachable), the calendar and booking use the API, owner sign-in is checked by the server, and the preview login file is left out of the build. Uploaded photo links need the API to have `API_PUBLIC_URL` set.

## Deploy

Vercel project `lutton-homes`: root directory `.` of this repository, build command `node build.mjs`, output `dist`. A push to `main` redeploys in 30 to 90 seconds. Set `API_URL` in the Vercel project settings when the API is hosted.

## Rules

- No third-party requests, self-hosted fonts, one `h1` per page, every image has alt, width and height, WCAG AA, no scroll event listeners.
- No em or en dashes in copy or assets. Sample values stay labelled "(sample)".
- Every new design is its own entry in the design dropdown with its own `/d/<id>/` site.
- Never commit secrets. Do not write passwords into docs.

## Workflow

`main` is protected by convention: work in a branch, open a pull request, CI must pass, then merge. Update this README in the same pull request when how the project runs or what is connected changes.
